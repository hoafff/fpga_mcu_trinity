AUDIT DISPOSITION
The v0.7.1 SN32 transport read the eight-byte SPI response header under one CS
assertion, released CS, then asserted CS again for the payload and CRC. The
Primer mailbox restarts its transmit byte index at zero on every CS falling
edge. Therefore responses longer than eight bytes were assembled from
non-contiguous data and could fail CRC or command/transaction correlation.

P2 RTL cannot issue TRANSACTION_CONFLICT for GET_INFO or GET_STATUS. It issues
that code only for a retained side-effect request that reuses the retained
transaction ID with a different command or request fingerprint. The clean-boot
gate had not reached RUN_SELF_TEST. The observed 0x0205 is therefore not accepted
as proof of a P2 retained-request conflict.

source=2 is a reported final error source, not proof that P2 was the first
endpoint to fail. The v0.7.1 probe routine probed P1 and then P2 even if P1 had
already failed, allowing the later source/detail to overwrite earlier telemetry.

related_target_txid was zero because GET_SYSTEM_INFO serialized a literal zero
and GET_INFO/GET_STATUS did not request the issued target transaction ID from
the transport. This is diagnostic loss, not evidence that target txid zero was
sent.
