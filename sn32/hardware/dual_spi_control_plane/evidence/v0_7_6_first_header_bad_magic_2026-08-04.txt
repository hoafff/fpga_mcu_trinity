POWER AND RESET AUDIT
- PC <-> SN32 UART PING passed in every reported run.
- SN32 was completely removed from power between runs.
- In a later run the SN32 common-ground wire was also removed while SN32 was
  unpowered; no board LED remained illuminated.
- P1 and P2 were reset before SN32 was reconnected in the final run.
- The failure class persisted, so PC UART back-power, SN32 power retention and
  the common-ground connection are not accepted as the explanation.

INTERPRETATION
- P1 accepted startup GET_INFO txid 0x0001 and built the correct response.
- The first SN32 read captured an invalid eight-byte header and released CS
  before consuming the 22-byte mailbox; IRQ therefore remained active.
- The later command recovered the valid old txid-0x0001 response with a valid
  CRC. TRANSACTION_CONFLICT was a correlation consequence, not a P1 command-core
  conflict.

CORRECTIVE DISPOSITION FOR V0.7.7
- reset SPI/FIFO while SPI is disabled before each CS window;
- restore completed-frame polling order: TX write, BUSY clear, RX ready, DATA read;
- if a malformed first header leaves IRQ active, retry the same pending mailbox
  under a fresh CS without issuing another request or allocating another txid;
- return immediately on P1 discovery failure before probing P2.
