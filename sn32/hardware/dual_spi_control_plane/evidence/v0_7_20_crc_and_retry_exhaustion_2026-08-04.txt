Interpretation locked for the v0.7.21 correction:

1. The startup response header declared a ten-byte frame, but its CRC was
   invalid and P1 IRQ remained active. v0.7.20 accepted the mailbox length
   before full CRC/decode validation and therefore did not perform the existing
   fresh-CS mailbox reread.
2. The periodic trace is a CRC-valid command=0/txid=0 BAD_LENGTH response with
   detail=0x00FF. It is the short/empty request signature. target_txid=0x000C is
   the final v0.7.20 read-only reissue, proving that one reissue was exhausted.
3. The PC timeouts are not accepted as an SN32 reset claim. v0.7.21 extends the
   host wait budget so a queued local command can survive bounded SPI recovery.
